## 🚀 Обзор проекта

**MyShell** - это полнофункциональный Unix-подобный командный интерпретатор, написанный на языке C. Проект реализует все основные возможности шелла, включая конвейеры, перенаправления ввода/вывода, логические операторы и фоновое выполнение команд.

### Основные возможности:
- ✅ Парсинг сложных команд с операторами
- ✅ Конвейеры (пайпы) `|`
- ✅ Перенаправления ввода/вывода `<`, `>`, `>>`
- ✅ Логические операторы `&&`, `||`
- ✅ Фоновое выполнение `&`
- ✅ Переменные окружения
- ✅ Многоуровневая обработка ошибок

## ✨ Особенности

### Поддерживаемые конструкции:
1. **Простые команды**: `ls -la`, `pwd`
2. **Конвейеры**: `who | wc -l`, `cat file.txt | grep "text" | sort`
3. **Перенаправления**: 
   - `cat > output.txt` (перезапись)
   - `cat >> output.txt` (добавление)
   - `cat < input.txt` (чтение из файла)
4. **Логические операторы**:
   - `cmd1 && cmd2` (выполнить cmd2 только если cmd1 успешна)
   - `cmd1 || cmd2` (выполнить cmd2 только если cmd1 неуспешна)
5. **Фоновый режим**: `sleep 10 &`
6. **Комбинации**: `cmd1 | cmd2 > file.txt && cmd3`

### Примеры работы:
```bash
# Конвейер с перенаправлением
myshell> who | cat > who_am_i.txt | cat | cat | cat > who_am_i_not.txt

# Дописывание в файл
myshell> pwd | cat >> my_home.txt

# Чтение из устройства и запись в файл
myshell> cat < /dev/urandom | head -c 4096 > "file.bin"

# Логические операторы
myshell> ls nonexistent || echo "File not found"
myshell> ls . && echo "Directory exists"

# Фоновое выполнение
myshell> sleep 5 &
```

## 📄 Файлы проекта

### 1. **lexer.h / lexer.c** - Лексический анализатор

**Основные функции:**
- `tokenize_input()` - разбивает входную строку на токены
- `expand_environment_vars()` - заменяет переменные окружения
- `add_token()` - добавляет токен в список
- `clear_token_list()` - освобождает память токенов

**Поддерживаемые токены:**
- Слова (имена команд, аргументы, имена файлов)
- Операторы: `|`, `&`, `;`, `&&`, `||`
- Операторы перенаправления: `<`, `>`, `>>`
- Кавычки и экранирование
- Комментарии (символ `#`)

### 2. **tree.h / tree.c** - Синтаксический анализатор

**Структура дерева команд:**
```c
typedef struct Tree {
    char **argv;           // Аргументы команды
    char *infile;          // Входной файл (<)
    char *outfile;         // Выходной файл (>, >>)
    int backgrnd;          // Фоновый режим (1/0)
    next_type type;        // Тип связи (NXT, AND, OR)
    int append;            // Режим дополнения файла
    struct Tree *pipe;     // Следующая команда в конвейере
    struct Tree *next;     // Следующая команда после ; && ||
} tree;
```

**Функции парсера (рекурсивный спуск):**
- `build_tree()` - основная функция построения дерева
- `com_sh()` - обработка последовательности команд
- `com_list()` - обработка списка команд с && и ||
- `conv()` - обработка конвейеров
- `simple_com()` - обработка простых команд с перенаправлениями

**Грамматика:**
```
com_sh ::= com_list ['&'] | com_list [';' com_sh]
com_list ::= conv { ('&&' | '||') conv }
conv ::= command { '|' command }
command ::= simple_com
simple_com ::= WORD { WORD } { ('<' | '>' | '>>') WORD }
```

### 3. **executor.h / executor.c** - Исполнитель команд

**Основные функции:**
- `execute_tree()` - выполняет дерево команд
- `execute_pipeline()` - выполняет конвейер команд
- `execute_single_command()` - выполняет одиночную команду
- `setup_redirections()` - настраивает перенаправления

**Особенности реализации:**
- Правильная обработка дескрипторов файлов
- Создание процессов через `fork()` и `execvp()`
- Ожидание завершения процессов через `waitpid()`
- Корректное закрытие pipe дескрипторов

### 4. **main.c** - Основной цикл шелла

**Основной цикл:**
1. Чтение ввода пользователя
2. Лексический анализ (токенизация)
3. Синтаксический анализ (построение дерева)
4. Исполнение команд
5. Очистка памяти

**Особенности:**
- Динамическое выделение памяти для ввода
- Обработка сигналов через `setjmp/longjmp`
- Поддержка команды `exit`

## 🔧 Технические детали

### Обработка ошибок
- Лексические ошибки: неверные символы, незакрытые кавычки
- Синтаксические ошибки: неверная последовательность операторов
- Системные ошибки: ошибки fork, exec, открытия файлов
- Использование `setjmp/longjmp` для обработки ошибок парсера

### Управление памятью
- Динамическое выделение памяти под строки
- Правильное освобождение всех ресурсов
- Защита от утечек памяти через `clear_tree()` и `clear_token_list()`

### Безопасность
- Проверка всех возвращаемых значений системных вызовов
- Защита от переполнения буферов
- Корректная обработка NULL-указателей

## 📊 Пример дерева команд

Для команды: `who | cat > output.txt && echo "Done"`

Дерево будет выглядеть так:
```
Команда на уровне 0:
  Аргументы: who
  Тип связи: AND (&&)
  Следующая в конвейере (|):
    Команда на уровне 1:
      Аргументы: cat
      Выходной файл: output.txt
  Следующая команда (тип: &&):
    Команда на уровне 0:
      Аргументы: echo "Done"
```
